# SparkMinds Passport 智能打卡机固件

这是运行在 ARCS-MINI (ESP32) 硬件上的 **SparkMinds Passport 智能打卡机** 固件项目。它作为学员的物理“数字护照”，主要用于校区内的人员签到、身份鉴权、在馆时长统计以及积分（XP）管理。

**硬件配置规格**：
* **屏幕显示**：配备 **240x240** 分辨率的 LCD 彩色屏幕，完美支持定制化像素风（Pixel UI）界面的展示。
* **持久化存储**：利用内置的非易失性 Flash 存储空间（NVS），为系统提供大容量的离线 KV 缓存能力，用于保存凭证、积分和流水。

## 🌟 核心功能特性

### 1. 动态防伪身份鉴权 (Dynamic Auth)
* **动态二维码**：设备使用内置的专属密钥（Secret），通过 HMAC-SHA256 加密算法每 30 秒自动生成一次动态防伪二维码。
* **离线可用**：二维码的生成纯依赖本地时钟与加密算法，在设备离线（无 Wi-Fi）状态下依然可以出示给老师进行扫码鉴权或下发积分。

### 2. 在馆心跳与自动结算 (Lab Presence)
* **自动签到**：当设备连接到校区专属 Wi-Fi（如 `SparkMinds_IoT`）并完成 NTP 自动校时后，会自动向后台同步状态。
* **无感挂机心跳**：设备每 10 分钟自动向后台发送一次“心跳包（Heartbeat）”，维持你的“在馆中”状态。
* **离馆惰性结算**：当你离开校区断开网络，后台在 15 分钟未收到心跳后会自动闭合你的在馆区间。若在馆总时长 $\ge$ 30 分钟，系统将自动下发 `LAB_VISIT` 奖励（10 积分）。

### 3. 本地化交互 UI (5 大核心界面)
项目基于 LVGL 图形库开发了高度定制化的像素风（Pixel UI）界面，通过设备按键进行切换：
1. **主菜单 (Menu)**：功能导航中枢。
2. **身份主页 (Identity)**：展示学员头像、姓名、Passport ID 及当前“是否在馆”的实时状态。
3. **二维码展示页 (QR)**：全屏展示高对比度的动态二维码，供扫码设备核验。
4. **我的积分与流水 (Points)**：实时展示学员的当前总积分余额（Points/XP），以及最新的账单流水明细（如打卡加分、活动扣分等）。
5. **系统设置 (Settings)**：查看上次同步时间、固件版本、网络状态。长按 OK 键 5 秒可进入隐藏的“Demo 演示模式”。

### 4. 离线缓存与可靠性 (Offline Cache)
* **KV 存储**：利用底层 `passport_store`，将学员的凭证、积分余额、流水记录等持久化存储在 Flash 中。
* **断电保护**：即使设备重启或断网，UI 依然可以无缝展示上次缓存的积分和身份信息，并在网络恢复后自动发起后台同步任务（Sync）。

### 5. 安全 OTA 固件升级与云端版本感知 (Safe OTA & Cloud Versioning)
* **学员数据与学号绝对安全隔离**：
  - **物理隔离**：固件仅烧录/OTA到 `ap` 分区（`0x00040000`）和 `app` 分区（`0x00600000`）；学员的学号（如 `SM-2026-048`）、积分流水、Token 等全部持久化在 Flash 尾部的 `kv` 分区（`0x00F00000`），**OTA 升级物理上绝不触碰学员数据**。
  - **软件守卫**：`passport_app.c` 具备出厂防覆盖守卫，只要检测到已有学员身份，升级后绝不覆盖重写。
* **防变砖防御流水线 (Defensive Pipeline)**：
  - **首包魔数校验**：首包必须为合法的 XZ 归档头（`0xFD '7' 'z' 'X' 'Z' 0x00`），避免非固件垃圾数据损坏暂存区。
  - **字节精确校验**：防止网络中断导致的残缺固件。
  - **MD5 流式完整性校验**：通过 `mbedtls/md5` 全程边下边算，指纹不符坚决拦截。
  - **U-Boot 联动**：全部校验 100% 通过后才登记到 `boot_control` 分区，由 Bootloader 执行双阶段安全解压写入。
* **云端版本动态检测与一键无缝升级**：
  - **无侵入元数据端点**：基于 Cloudflare R2 直链 `https://api.sparkminds.io/api/files/avatars/ota_info.jpg`，无需后端任何侵入性修改。
  - **自动与按需检测**：Wi-Fi 连接成功即自动后台异步检测；也可在 **05 SETTINGS**（设置页）按 OK 键随时检测。
  - **UI 动态提示**：
    - 已是最新版：显示 `固件: v1.0.1 (已最新)`
    - 发现新版本：显示 `发现新版: <版本号> (按OK)`，点击 OK 键直接启动一键升级。
  - **终端 CLI 支持**：
    - `ota check`：查询云端最新版本。
    - `ota update`：一键触发升级到云端最新版。

## 🔄 免修改代码：串口 / ADB 一键切换学员身份 (Student Provision)

设备固件内置花名册解析引擎与安全发卡指令。在无需重新编译代码、无需重新烧录固件的情况下，只需通过**串口助手**或 **ADB Shell** 即可随时将设备切换为花名册中的任意学员账号（会自动清空上一位学员的历史 Token、余额与头像缓存，写入新学员的硬件密钥并安全重置）：

### 1. 串口终端切换步骤（推荐）
1. 使用 USB 数据线或串口线连接设备，打开任意串口终端工具（如 MobaXterm、PuTTY、SSCOM、VSCode Serial Monitor 等）：
   - **波特率**：`115200`
   - **数据位/停止位**：`8-N-1`
   - **端口**：选择对应的 COM 口（如 `COM4`）
2. 在控制台中输入切换指令并回车：
   ```bash
   provision 002    # 一键切换为 陆昭闻（Owen）
   ```
   *(亦可输入完整学号：`provision SM-2026-002`)*
3. 终端将输出确认日志：
   ```text
   正在写入学员身份：陆昭闻（Owen） (SM-2026-002)
   写入成功！学员身份已就绪：陆昭闻（Owen） (SM-2026-002)
   ```
4. 按复位键或断电重启设备后，屏幕即直接显示为目标学员账号。

### 2. ADB Shell 切换步骤
若设备已连接电脑且处于运行状态，在命令行直接运行内置 ADB 即可完成一键切换：
```powershell
# Windows
.\tools\adb\adb.exe shell provision 002

# Linux / Mac
./tools/adb/adb shell provision 002
```

## 📂 代码架构导读
* **`passport_app.c`**：核心应用层。管理主事件循环、心跳定时器（10分钟）、NTP 校时触发逻辑、出厂学号防覆盖保护。
* **`passport_net.c`**：网络通信层。封装了基于 Token 的 HTTPS 请求（处理 `/verify`、`/auth`、`/heartbeat`、`/me` 等 API），具有 Token 过期自动刷新机制。
* **`passport_ota.c` / `passport_ota.h`**：安全 OTA 引擎与云端版本检测模块。负责 XZ 头校验、MD5 完整性核验、向云端查询版本以及与 U-Boot 交互。
* **`passport_crypto.c`**：安全加密层。负责底层 HMAC 签名计算与密码学安全。
* **`passport_ui.c`**：图形渲染层。负责绘制 5 个核心屏幕、版本与网络状态实时刷新，并响应按键事件。
* **`passport_store.c`**：数据持久化层。管理 Flash KV 分区存储。

## 🚀 后续规划与已知机制
* **时间同步强制依赖**：设备的鉴权与心跳强依赖于准确的北京时间，必须确保 `sys_time_sync()` 正常运行。
* **首次心跳延迟**：受限于目前的 Timer 逻辑设计，设备开机后的“首发心跳”会在开机满 10 分钟后才发出。
